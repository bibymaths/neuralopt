## Result

**No family meets the F0 stop rule (`B95_multi ≤ 2·c_local`), so all three proceed.** The
substance differs sharply by family:

| | Family 1 (sinusoid) | Family 2a (clean cascade, control) | Family 2b (realistic cascade) |
|---|---|---|---|
| `c_local` (median units, A0) | 83.5 | 165.5 | 208 |
| `B95_multi` (better of A2, A2o) | > 800 | 400 | 800 |
| Stop rule (`B95_multi ≤ 2·c_local`) | no stop (> 800 vs 167) | no stop (400 vs 331) | no stop (800 vs 416) |
| Nearest neighbour amortizes (A3 `B95 ≤ 2·c_local`) | no (A3 never reaches 95%) | **yes** (200 ≤ 331) | no (800) |
| Headroom for a learned start | **large** | **small**: the default start already gives B95 = 100 | **moderate**, in units |

- **Family 1 has large headroom, and the lookup is the bar to beat.**
  - No generic arm reaches 95% success within 800 units. The best is owned multistart at
    84.5%.
  - The nearest-neighbour start (A3) is by far the strongest arm at small budgets: 57%
    at 50 units and 74.5% at 100, against 17.5% and 48.5% for the default start and 0%
    and 5% for multistart. It then plateaus at 74.5%.
  - A learned predictor must beat this lookup (claim C3), not just the generic arms.
- **Family 2a has little headroom.**
  - The default start alone (A0) reaches 95% success at 100 units and 100% at 200. The
    lookup's flag is set (A3 B95 = 200).
  - The stop rule passes only because it compares against multistart. Against the
    default start, a learned start could save units only below 100 (A0: 15.5% at 50
    units).
  - Family 2a was designed as the control, and it behaves like one.
- **Family 2b has moderate headroom, measured in units.**
  - Every arm needs 800 units for 95% success. The default start is the best generic arm
    at every budget from 100 units (61.5% at 100, 84% at 200, 94.5% at 400).
  - Multistart is worse at ≤ 400 units because it splits the budget.
  - The lookup does not help: A3 is below A0 at 100–400 units.
  - **28% of checked instances are not identifiable** (Fisher condition > 1e6). Parameter
    error on Family 2b must be reported only with the identifiability check (plan §6).

- The owned L-BFGS charges an objective call per line-search trial and a gradient only on
  acceptance, so objective calls outnumber gradient calls 2.3–3.2×.
- SciPy arms charge one objective plus one gradient (2 units) per call. Total SciPy calls,
  including the references: 1.16 M, 2.16 M and 2.43 M.
- F0's probe measured the gradient at 2.5× (Family 1) and about 12× (Family 2) the cost
  of an objective call. Unit counts therefore understate the cost of gradient-heavy arms
  on Family 2.

## Deviations and caveats (reported plainly)

1. **The CPU cap was exceeded on process CPU time.**
   - Process CPU time was **8.61 h**: 0.93 h, 3.65 h and 4.03 h per family. The cap was
     6 CPU-hours.
   - Wall time was 1.32 h.
   - The timing probe projected 2.57 h from single-threaded per-call timings. That
     projection was right for wall time, but process CPU also counts helper threads:
     CPU/wall was 9.6×, 6.5× and 6.1× per family.
   - The aborted first run used a further 72 minutes of wall time; its CPU time was not
     recorded.
   - The cap was not enforced during the run. **Future caps (including v0.8-B's 24
     CPU-hours) must state which clock they bound, and thread counts should be pinned.**
2. **A1 and A2 use SciPy's default stopping tolerances**; the reference uses tight ones.
   - An exploratory diagnostic (not part of the F0 protocol) re-ran A1 with tight
     tolerances.
   - **Family 1:** default and tight end at the same values (they differ beyond
     tolerance on 2.5% of instances). A1's weaker success comes from SciPy's line search
     ending in different basins.
   - **Family 2b (60 instances):** SciPy's final value was worse than the owned solver's
     on 15% of instances with default tolerances and 6.7% with tight ones. About half
     of A1's gap there is early stopping.
   - `B95_multi` takes the better of A2 and A2o, so this does not push the stop rule
     toward stopping.
3. **The stop rule compares against multistart only.** On Family 2a the default start
   already does what the rule asks of a learned start. **Recommendation for the
   pre-registration (stop point 3):** make the default start (A0) a required bar, next to
   the lookup (A3), for every cost claim (C1, C2, C4), per family.
4. **B95 is read on a coarse grid** (25 to 800, doubling). "800" means somewhere in
   (400, 800].
