# NeuralOpt v0.2.0

Released 2026-11-15 (UTC merge date) · PR #2 · [commits](https://github.com/bibymaths/neuralopt/compare/v0.1.0...v0.2.0)

> Research foundation for outcome-driven training, trajectory diagnostics, certified scheduling and opt-in Hamiltonian proposals, with smoke-scale evidence only. Result type: infrastructure.

This release was tagged retroactively on 2026-11-22; it was not published to PyPI.

## Highlights

- Differentiable multi-horizon regret training through unrolled updates.
- Trajectory diagnostics that diagnose the v0.1 policy's failure: good directions,
  but steps that are too long and a proposal head that is never accepted.
- Opt-in native JAX Hamiltonian (HMC) proposals with explicit cost accounting.
- Certificate replay now checks domain coverage and non-overlap of retained boxes.

## Features

- `unrolled_regret_loss`: `lax.scan` unrolling with robust normalized best-so-far regret;
  requires an explicit known optimum.
- Normalized box-coordinate transforms for positions and gradients, round-trip tested.
- A matched-input MLP policy as an architecture ablation (no attention).
- Evaluation-neutral trajectory diagnostics: one row per objective evaluation, no extra
  calls.
- Certification scheduling controls (lower-bound or width priority, widest or
  round-robin splitting) and callbacks for learned ranking. Callbacks affect only the
  order of work, never bounds, pruning or termination.
- `candidate_method="hamiltonian"`: leapfrog with Metropolis correction, logistic box
  transform with its Jacobian, fixed or learned diagonal-plus-low-rank mass, and a
  separate feasible incumbent.

## Research results

Infrastructure with smoke-scale evidence only; the outcome-trained smoke checkpoint is a
negative result and is not promoted.

- Outcome-training smoke (12 meta-updates): the checkpoint worsened an unseen 8D rotated
  quadratic from 89.41 to 164.71. It is kept as `neuralopt-v0.2.0-smoke.npz`.
- A fixed normalized-gradient control beats v0.1.0 on every recorded smoke family. Each
  family is a single instance, so this is not a superiority claim.
- Diagnostics: v0.1 directions have median descent cosine 0.833–0.999, yet acceptance
  is 0–4.1%; the proposal head uses 24 of 49 evaluations and is never accepted.
- HMC smoke (15 instances, three seeds): identity HMC beats direct on 8/15 pairs and
  learned-metric HMC on 9/15, but learned beats identity on only 7/15. Learned mass
  geometry is not supported (H2).
- Certification: no learned scheduling policy was trained, so no speedup is claimed.

## Fixes

- After a rejected candidate, `x` moved without being evaluated, so its stored value no
  longer matched its gradient. The current state now stays unchanged after rejection.
- Certificate replay closes the v0.1.0 domain-accounting omission (volume and overlap
  checks).
- Benchmarks enforce evaluation budgets strictly and handle nonfinite samples without
  replacing a valid incumbent.
- Training regularizers compare directions and gradients in the same normalized
  coordinates.
- Regret-training numerics hardened; learned-policy architecture parameters validated;
  HMC chain state preserved exactly between transitions.

## Known limitations

- All evidence is smoke-scale (single instances or 15 instances, three seeds).
- Hamiltonian proposals are opt-in. History-adaptive learned metrics have no
  stationary-distribution claim.
- Hamiltonian incumbents are not injected into certified search.
- The retroactive release workflow does not rerun the test suite at this tag.
